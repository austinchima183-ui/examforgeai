    21→## Overview
    22→
    23→The ExamForge AI backend is powered by **Supabase**, which provides:
    24→
    25→- **PostgreSQL database** with Row Level Security (RLS)
    26→- **Auto-generated REST API** for all tables (PostgREST)
    27→- **RPC (Remote Procedure Call)** endpoints for custom SQL functions
    28→- **Real-time subscriptions** via WebSocket
    29→- **Authentication** via Supabase Auth (email/password, OAuth, MFA)
    30→- **Storage** for file uploads (documents, images, media)
    31→
    32→### Base URL
    33→
    34→```
    35→https://<project-ref>.supabase.co/rest/v1
    36→```
    37→
    38→### Common Headers
    39→
    40→```http
    41→apikey: <your-anon-key-or-service-key>
    42→Authorization: Bearer <user-access-token>
    43→Content-Type: application/json
    44→Prefer: return=representation
    45→```
    46→

    49→## Authentication
    50→
    51→### Authentication Methods
    52→
    53→| Method | Description |
    54→|--------|-------------|
    55→| Email/Password | Standard email and password login via Supabase Auth |
    56→| OAuth | Google, Apple, Microsoft providers |
    57→| MFA | SMS, email, authenticator app, hardware key |
    58→| API Keys | Scoped API keys with rate limit overrides |
    59→
    60→### Role-Based Access
    61→
    62→The system uses a `role` field in `auth.users.raw_user_meta_data` to determine access levels:
    63→
    64→| Role | Access Level |
    65→|------|-------------|
    66→| `superAdmin` | Full platform access, all schools, security, monitoring |
    67→| `schoolAdmin` | School-scoped admin, curriculum management, user management |
    68→| `teacher` | Content creation, review, AI generation |
    69→| `student` | Read-only access to published content, practice mode |
    70→| `parent` | Read-only access to child's curriculum and progress |
    71→
    72→### Row Level Security (RLS)
    73→
    74→All tables have RLS enabled. Access policies are summarized below:
    75→
    76→| Table | Read Access | Write Access |
    77→|-------|-----------|-------------|
    78→| `educational_levels` | All authenticated users | Super admins only |
    79→| `school_level_configurations` | School members | School admins |
    80→| `curricula` | All authenticated users | Admins |
    81→| `subjects` | School members | Admins |
    82→| `topics` | School members | Teachers and admins |
    83→| `content_items` | Published content or school members | Creators and admins |
    84→| `content_reviews` | Via content access | Reviewers (teachers+) |
    85→| `content_collections` | Public or school members | Creators and admins |
    86→| `ai_curriculum_configs` | School members | Admins |
    87→| `audit_trail` | Super admins only | System (insert only) |
    88→| `security_events` | Super admins only | System (insert only) |
    89→| `user_sessions` | Own sessions only | Owner or super admin |
    90→| `system_metrics` | Admins | System |
    91→| `performance_logs` | Super admins only | System |
    92→
    93→### Obtaining an Access Token
    94→
    95→```bash
    96→# Sign in with email/password
    97→curl -X POST 'https://<project-ref>.supabase.co/auth/v1/token?grant_type=password' \
    98→  -H 'apikey: <anon-key>' \
    99→  -H 'Content-Type: application/json' \
   100→  -d '{"email": "teacher@school.edu.ng", "password": "securepassword"}'
   101→```
   102→
   103→Response:
   104→
   105→```json
   106→{
   107→  "access_token": "eyJhbGciOiJIUzI1NiIs...",

   109→  "expires_in": 3600,

   125→## Rate Limiting
   126→
   127→Rate limiting is enforced at the database level via the `check_rate_limit` RPC function and at the API gateway level.
   128→
   129→### Rate Limit Scopes
   130→
   131→| Scope | Description |
   132→|-------|-------------|
   133→| `global` | Platform-wide limits |
   134→| `per_user` | Per authenticated user |
   135→| `per_ip` | Per IP address |
   136→| `per_api_key` | Per API key |
   137→| `per_endpoint` | Per specific API endpoint |
   138→
   139→### Default Limits
   140→
   141→| Scope | Limit | Window |
   142→|-------|-------|--------|
   143→| `global` | 10,000 req/min | 60 seconds |
   144→| `per_user` | 1,000 req/min | 60 seconds |
   145→| `per_ip` | 500 req/min | 60 seconds |
   146→| `per_api_key` | Configurable | Configurable |
   147→
   148→### Rate Limit Headers
   149→
   150→```http
   151→X-RateLimit-Limit: 1000
   152→X-RateLimit-Remaining: 942
   153→X-RateLimit-Reset: 1677654321
   154→```
   155→
   156→When rate-limited, the API returns:
   157→
   158→```json
   159→{
   160→  "code": 429,
   161→  "message": "Rate limit exceeded",
   162→  "retry_after": 45
   163→}
   164→```

   170→### `get_school_levels`
   171→
   172→Retrieves all educational levels with their enablement status for a specific school.
   173→
   174→**Parameters:**
   175→
   176→| Name | Type | Required | Description |
   177→|------|------|----------|-------------|
   178→| `p_school_id` | UUID | Yes | The school ID |
   179→
   180→**Returns:** Table of levels with enablement info
   181→
   182→| Column | Type | Description |
   183→|--------|------|-------------|
   184→| `id` | UUID | Level ID |
   185→| `code` | TEXT | Level code (e.g., `primary_1`) |
   186→| `name` | TEXT | Display name (e.g., "Primary 1") |
   187→| `level_category` | level_category_type | Category enum |
   188→| `level_order` | INT | Sort order |
   189→| `min_age` | INT | Minimum age |
   190→| `max_age` | INT | Maximum age |
   191→| `description` | TEXT | Level description |
   192→| `is_enabled` | BOOLEAN | Whether enabled for this school |
   193→| `custom_name` | TEXT | School-specific name override |
   194→

   196→
   197→```bash
   198→curl -X POST 'https://<project-ref>.supabase.co/rest/v1/rpc/get_school_levels' \

   200→  -H 'Authorization: Bearer <token>' \
   201→  -H 'Content-Type: application/json' \

   464→### `check_rate_limit`
   465→
   466→Checks whether a request is within rate limits before processing.
   467→
   468→**Parameters:**
   469→
   470→| Name | Type | Required | Description |
   471→|------|------|----------|-------------|

   473→| `p_identifier` | TEXT | Yes | Identifier within scope |

   475→
   476→**Returns:** Table with three columns

   482→| `reset_at` | TIMESTAMPTZ | When the window resets |
   483→
   484→**Example:**
   485→
   486→```bash
   487→curl -X POST 'https://<project-ref>.supabase.co/rest/v1/rpc/check_rate_limit' \
   488→  -H 'apikey: <anon-key>' \
   489→  -H 'Authorization: Bearer <token>' \
   490→  -d '{"p_scope": "per_user", "p_identifier": "user-uuid", "p_endpoint": "/rest/v1/content_items"}'
   491→```
   492→
   493→**Response:**
   494→
   495→```json
   496→[{"allowed": true, "remaining": 942, "reset_at": "2024-01-15T10:31:00Z"}]

   641→#### SELECT (Read)
   642→
   643→```bash

   650→**Query Operators:**
   651→
   652→| Operator | Meaning | Example |
   653→|----------|---------|---------|
   654→| `eq` | Equals | `status=eq.published` |
   655→| `neq` | Not equals | `status=neq.archived` |
   656→| `gt` | Greater than | `usage_count=gt.100` |
   657→| `gte` | Greater than or equal | `quality_score=gte.3.5` |
   658→| `lt` | Less than | `created_at=lt.2024-01-01` |
   659→| `like` | Pattern match | `title=like.*algebra*` |
   660→| `ilike` | Case-insensitive pattern | `title=ilike.*Algebra*` |
   661→| `in` | In list | `difficulty_level=in.(beginner,elementary)` |
   662→| `is` | Is null / true | `reviewed_by=is.null` |
   663→| `cs` | Contains (array) | `tags=cs.{mathematics}` |

   856→## Webhook Patterns
   857→
   858→### Available Webhooks
   859→
   860→| Event | Trigger | Payload |
   861→|-------|---------|---------|
   862→| `content.published` | Content item status changes to `published` | Content item object |
   863→| `content.review_requested` | Content submitted for review | Content item + reviewer info |
   864→| `import.completed` | Bulk import finishes | Import stats |
   865→| `security.alert` | Security event with severity ≥ `critical` | Security event object |
   866→| `alert.fired` | Monitoring alert triggers | Alert incident object |
   867→| `deployment.completed` | Deployment finishes | Deployment object |
   868→
   869→### Webhook Registration
   870→
   871→Webhooks are registered via the Supabase Edge Functions or the `alert_rules.notification_channels` field:
   872→
   873→```json
   874→{
   875→  "notification_channels": ["email:admin@school.edu.ng", "webhook:https://your-server.com/hook"]
   876→}
   877→```
   878→
   879→### Webhook Payload Example
   880→
   881→```json
   882→{
   883→  "event": "content.published",
   884→  "timestamp": "2024-01-15T10:30:00Z",
   885→  "data": {
   886→    "id": "content-uuid",
   887→    "title": "Solve for x: 2x + 5 = 15",
   888→    "content_type": "question",
   889→    "subject_name": "Mathematics",
   890→    "level_name": "Primary 5",
   891→    "published_by": "teacher-uuid",
   892→    "school_id": "school-uuid"
   893→  },
   894→  "signature": "sha256=abcdef1234567890..."
   895→}
   896→```
   897→
   898→### Webhook Verification
   899→
   900→Always verify webhook signatures:
   901→
   902→```dart
   903→import 'package:crypto/crypto.dart';
   904→
   905→bool verifyWebhookSignature(String payload, String signature, String secret) {
   906→  final key = utf8.encode(secret);
   907→  final bytes = utf8.encode(payload);
   908→  final hmacSha256 = Hmac(sha256, key);
   909→  final digest = hmacSha256.convert(bytes);
   910→  final expected = 'sha256=${digest.toString()}';
   911→  return signature == expected;
   912→}
   913→```
   914→
   915→### Retry Policy
   916→
   917→Failed webhook deliveries are retried with exponential backoff:
   918→
   919→| Attempt | Delay |
   920→|---------|-------|
   921→| 1 | Immediate |
   922→| 2 | 1 minute |
   923→| 3 | 5 minutes |
   924→| 4 | 30 minutes |
   925→| 5 | 2 hours |
   926→
   927→After 5 failed attempts, the webhook is marked as failed and an alert is generated.
