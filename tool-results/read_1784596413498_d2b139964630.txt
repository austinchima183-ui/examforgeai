    21→    21→## Overview
    22→    22→
    23→    23→The ExamForge AI backend is powered by **Supabase**, which provides:
    24→    24→
    25→    25→- **PostgreSQL database** with Row Level Security (RLS)
    26→    26→- **Auto-generated REST API** for all tables (PostgREST)
    27→    27→- **RPC (Remote Procedure Call)** endpoints for custom SQL functions
    28→    28→- **Real-time subscriptions** via WebSocket
    29→    29→- **Authentication** via Supabase Auth (email/password, OAuth, MFA)
    30→    30→- **Storage** for file uploads (documents, images, media)
    31→    31→
    32→    32→### Base URL
    33→    33→
    34→    34→```
    35→    35→https://<project-ref>.supabase.co/rest/v1
    36→    36→```
    37→    37→
    38→    38→### Common Headers
    39→    39→
    40→    40→```http
    41→    41→apikey: <your-anon-key-or-service-key>
    42→    42→Authorization: Bearer <user-access-token>
    43→    43→Content-Type: application/json
    44→    44→Prefer: return=representation
    45→    45→```

    49→    49→## Authentication
    50→    50→
    51→    51→### Authentication Methods
    52→    52→
    53→    53→| Method | Description |
    54→    54→|--------|-------------|
    55→    55→| Email/Password | Standard email and password login via Supabase Auth |
    56→    56→| OAuth | Google, Apple, Microsoft providers |
    57→    57→| MFA | SMS, email, authenticator app, hardware key |
    58→    58→| API Keys | Scoped API keys with rate limit overrides |
    59→    59→
    60→    60→### Role-Based Access
    61→    61→
    62→    62→The system uses a `role` field in `auth.users.raw_user_meta_data` to determine access levels:
    63→    63→
    64→    64→| Role | Access Level |
    65→    65→|------|-------------|
    66→    66→| `superAdmin` | Full platform access, all schools, security, monitoring |
    67→    67→| `schoolAdmin` | School-scoped admin, curriculum management, user management |
    68→    68→| `teacher` | Content creation, review, AI generation |
    69→    69→| `student` | Read-only access to published content, practice mode |
    70→    70→| `parent` | Read-only access to child's curriculum and progress |
    71→    71→
    72→    72→### Row Level Security (RLS)
    73→    73→
    74→    74→All tables have RLS enabled. Access policies are summarized below:
    75→    75→
    76→    76→| Table | Read Access | Write Access |
    77→    77→|-------|-----------|-------------|
    78→    78→| `educational_levels` | All authenticated users | Super admins only |
    79→    79→| `school_level_configurations` | School members | School admins |
    80→    80→| `curricula` | All authenticated users | Admins |
    81→    81→| `subjects` | School members | Admins |
    82→    82→| `topics` | School members | Teachers and admins |
    83→    83→| `content_items` | Published content or school members | Creators and admins |
    84→    84→| `content_reviews` | Via content access | Reviewers (teachers+) |
    85→    85→| `content_collections` | Public or school members | Creators and admins |
    86→    86→| `ai_curriculum_configs` | School members | Admins |
    87→    87→| `audit_trail` | Super admins only | System (insert only) |
    88→    88→| `security_events` | Super admins only | System (insert only) |
    89→    89→| `user_sessions` | Own sessions only | Owner or super admin |
    90→    90→| `system_metrics` | Admins | System |
    91→    91→| `performance_logs` | Super admins only | System |
    92→    92→

   125→   125→## Rate Limiting
   126→   126→
   127→   127→Rate limiting is enforced at the database level via the `check_rate_limit` RPC function and at the API gateway level.
   128→   128→
   129→   129→### Rate Limit Scopes
   130→   130→
   131→   131→| Scope | Description |
   132→   132→|-------|-------------|
   133→   133→| `global` | Platform-wide limits |
   134→   134→| `per_user` | Per authenticated user |
   135→   135→| `per_ip` | Per IP address |
   136→   136→| `per_api_key` | Per API key |
   137→   137→| `per_endpoint` | Per specific API endpoint |
   138→   138→
   139→   139→### Default Limits
   140→   140→
   141→   141→| Scope | Limit | Window |
   142→   142→|-------|-------|--------|
   143→   143→| `global` | 10,000 req/min | 60 seconds |
   144→   144→| `per_user` | 1,000 req/min | 60 seconds |
   145→   145→| `per_ip` | 500 req/min | 60 seconds |
   146→   146→| `per_api_key` | Configurable | Configurable |
   147→   147→
   148→   148→### Rate Limit Headers
   149→   149→
   150→   150→```http
   151→   151→X-RateLimit-Limit: 1000
   152→   152→X-RateLimit-Remaining: 942
   153→   153→X-RateLimit-Reset: 1677654321
   154→   154→```
   155→   155→
   156→   156→When rate-limited, the API returns:
   157→   157→
   158→   158→```json
   159→   159→{
   160→   160→  "code": 429,
   161→   161→  "message": "Rate limit exceeded",
   162→   162→  "retry_after": 45
   163→   163→}
   164→   164→```

   172→   172→Retrieves all educational levels with their enablement status for a specific school.

   858→   858→### Available Webhooks
   859→   859→
   860→   860→| Event | Trigger | Payload |
   861→   861→|-------|---------|---------|
   862→   862→| `content.published` | Content item status changes to `published` | Content item object |
   863→   863→| `content.review_requested` | Content submitted for review | Content item + reviewer info |
   864→   864→| `import.completed` | Bulk import finishes | Import stats |

   880→   880→
   881→   881→```json
   882→   882→{
   883→   883→  "event": "content.published",
   884→   884→  "timestamp": "2024-01-15T10:30:00Z",
   885→   885→  "data": {
   886→   886→    "id": "content-uuid",
   887→   887→    "title": "Solve for x: 2x + 5 = 15",

   891→   891→    "published_by": "teacher-uuid",
   892→   892→    "school_id": "school-uuid"
   893→   893→  },
   894→   894→  "signature": "sha256=abcdef1234567890..."
   895→   895→}
   896→   896→```
   897→   897→
   898→   898→### Webhook Verification
   899→   899→
   900→   900→Always verify webhook signatures:
   901→   901→
   902→   902→```dart
   903→   903→import 'package:crypto/crypto.dart';
   904→   904→
   905→   905→bool verifyWebhookSignature(String payload, String signature, String secret) {
   906→   906→  final key = utf8.encode(secret);
   907→   907→  final bytes = utf8.encode(payload);
   908→   908→  final hmacSha256 = Hmac(sha256, key);
   909→   909→  final digest = hmacSha256.convert(bytes);
   910→   910→  final expected = 'sha256=${digest.toString()}';
   911→   911→  return signature == expected;
   912→   912→}
   913→   913→```
   914→   914→
   915→   915→### Retry Policy
   916→   916→
   917→   917→Failed webhook deliveries are retried with exponential backoff:
   918→   918→
   919→   919→| Attempt | Delay |
   920→   920→|---------|-------|
   921→   921→| 1 | Immediate |
   922→   922→| 2 | 1 minute |
   923→   923→| 3 | 5 minutes |
   924→   924→| 4 | 30 minutes |
   925→   925→| 5 | 2 hours |
   926→   926→
   927→   927→After 5 failed attempts, the webhook is marked as failed and an alert is generated.
